# BauLens

AI-assisted construction material inspection: concrete compressive-strength prediction (tabular ML),
crack detection in concrete surface images (computer vision), and German inspection-report drafts
generated by a local LLM with a numeric faithfulness check.

> Work in progress. Development is tracked in the [milestones](../../milestones) and [pull requests](../../pulls).

## Run locally

The API loads trained models from `artifacts/`; weights are not in git. Train them first with
`make data strength cracks` (roughly 20 min for strength and 45 min for the crack model on a laptop CPU). Without
them the API still starts and reports the missing components in `/health` and the dashboard.

With uv, in two terminals:

```sh
uv run --locked baulens api serve          # http://localhost:8000/api/v1/docs
cd apps/dashboard && uv run --locked streamlit run app.py   # http://localhost:8501
```

With Docker Compose (artifacts are mounted read-only from `./artifacts`):

```sh
docker compose up --build                  # API, dashboard and Ollama (live report drafts)
docker compose -f docker-compose.yml -f docker-compose.demo.yml up --build   # demo: no Ollama
```

The full stack runs a one-shot `ollama-pull` service that downloads `BAULENS_LLM_MODEL`
(default `qwen2.5:3b`) into a named volume. The demo override sets `BAULENS_LLM_MODE=replay`:
live generation is refused and only recorded report output is served, labelled as such. See
[docs/architecture.md](docs/architecture.md) for the components and request flow.

## Development

Install [uv](https://docs.astral.sh/uv/getting-started/installation/) and run these commands from
the checkout. The project defaults to Python 3.12 and uses CPU builds of PyTorch on Linux and
Windows.

```sh
uv sync --locked
uv run --locked baulens --help
uv run --locked ruff check
uv run --locked ruff format --check
uv run --locked mypy
uv run --locked pytest -m "not slow" --cov --cov-report=term-missing
uv run --locked pytest -m smoke
```

With GNU Make, `make setup` installs the locked environment and `make all` runs the checks.
The tests use local fixtures and mocked HTTP and run without a GPU or Ollama.

Container images must use a glibc base such as `python:3.12-slim-bookworm`: ONNX Runtime and the
CPU PyTorch wheels have no musl (Alpine) builds, so `uv sync --locked` fails there.

| Make target | Commands without Make |
| --- | --- |
| `make data` | `uv run baulens data download all` |
| `make strength` | `uv run baulens strength train`, `uv run baulens strength evaluate` |
| `make cracks` | `uv run baulens cracks train`, `uv run baulens cracks evaluate`, `uv run baulens cracks export`, `uv run baulens cracks benchmark` |
| `make report` | `uv run baulens report generate`, `uv run baulens report compare` |
| `make api` | `uv run baulens api serve` |
| `make dashboard` | `cd apps/dashboard && uv run streamlit run app.py` |

Pipeline code lives in `src/baulens/`, the Streamlit dashboard is in `apps/dashboard/`, and
YAML settings live in `configs/` and `configs/smoke/`. See [CONTRIBUTING.md](CONTRIBUTING.md)
for module and output conventions.

### Strength

Run `make strength` after obtaining the concrete workbook. The [strength results](docs/results/strength.md)
cover unseen exact ingredient tuples, the random-row comparison, and prediction intervals. See the
[model card](docs/model_cards/strength.md) for intended use and the inference interface.

### Cracks

Run `make cracks` after `make data`. The [crack results](docs/results/cracks.md) cover the
duplicate-aware split, test metrics, a corruption probe, Grad-CAM and the ONNX benchmark. See the
[model card](docs/model_cards/cracks.md) for intended use and limitations.

### Datasets

Run `uv run baulens data download concrete` or `uv run baulens data download cracks` to fetch a
single dataset. The downloader verifies archive SHA-256 digests against
[`configs/datasets.yaml`](configs/datasets.yaml) and extracts files below `data/raw/`.

The cracks archive requires a RAR-capable tar. Windows 11 includes one in System32. On Debian
or Ubuntu, install `libarchive-tools` to get `bsdtar`. If automatic download or extraction is
unavailable, use the manual procedure.

1. Download the individual `.rar` from the [Mendeley dataset page](https://data.mendeley.com/datasets/5y9wdsg2zt/2)
   and save it as `data/raw/cracks.rar`. For concrete, save the [UCI ZIP](https://archive.ics.uci.edu/static/public/165/concrete+compressive+strength.zip)
   as `data/raw/concrete.zip`.
2. Rerun `uv run baulens data download cracks` or `uv run baulens data download concrete`.
   The downloader checks a manually supplied archive before extraction.
3. If you need to extract the RAR with another tool such as 7-Zip, compare
   `Get-FileHash data/raw/cracks.rar -Algorithm SHA256` in PowerShell or
   `sha256sum data/raw/cracks.rar` on Linux with the manifest before extracting. Extract into
   `data/raw/cracks/` so it directly contains `Positive/` and `Negative/`, then rerun the
   downloader to validate the archive and image counts.

See [DATA_LICENSES.md](DATA_LICENSES.md) and [NOTICE](NOTICE) for dataset terms and citations.
